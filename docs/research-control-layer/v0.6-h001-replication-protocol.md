# v0.6-D1 — H-001 Independent Mini-Replication Protocol

**Status:** Protocol Draft 0.1 — execution pending  
**Research Gate:** v0.6 Research Gate (#22)  
**Hypotheses:** H-001 / H-002  
**Control baseline:** ACAA `v0.5.0`  
**Canonical release target:** `de7d11ed9457ede84c1954aa70a59331bf07b72e`  
**Governance state:** `FROZEN`

## 1. Purpose

Determine whether an independent operator can reconstruct the declared v0.5 baseline procedure from the repository's published procedures and artifacts, without undocumented project-specific assumptions.

This is a reproducibility experiment. It does not modify the v0.5 baseline, move the `v0.5.0` tag, or promote any v0.6 hypothesis to evidence merely by execution.

## 2. Hypotheses

### H-001
An independent party can reconstruct the declared baseline procedure.

- **Independent variable:** replication operator and use of the declared procedure.
- **Dependent variable:** successful reconstruction of the required baseline outputs.
- **Falsification condition:** one or more required outputs cannot be reconstructed from the published procedure and artifacts.

### H-002
Documentation contains sufficient information for independent reproduction.

- **Independent variable:** documentation available to the operator.
- **Dependent variable:** reproduction sufficiency.
- **Falsification condition:** reproduction requires missing information, undocumented assumptions, or unavailable artifacts.

## 3. Immutable control point

The replication MUST begin from the exact release target:

```text
v0.5.0 → de7d11ed9457ede84c1954aa70a59331bf07b72e
```

The operator must record:

1. `git rev-parse HEAD`
2. `git describe --tags --exact-match` (expected: `v0.5.0`)
3. repository URL
4. operating system
5. Python version
6. complete command transcript
7. SHA-256 hashes of relevant input files and produced artifacts

Any deviation from the canonical target must be recorded as a protocol deviation and the run must not be treated as a baseline replication.

## 4. Required repository inputs

At minimum, the replication environment must contain the files present in the frozen release that are required by the declared O1 procedure:

- `value_flow_simulator_v0.4.py`
- `o1_robustness_v0_5.py`
- `independent_o1_validator_v0_5.py`
- `prepare_o1_independent_evidence_v0_5.py`
- `tests/test_o1_robustness_v0_5.py`
- `tests/test_independent_o1_validator_v0_5.py`
- the v0.5 governance/research documentation needed to interpret the procedure

The frozen release also contains the O2 implementation and validation artifacts; they are part of the baseline inventory but are outside the first H-001 execution unless the replication scope is explicitly expanded.

## 5. Environment reconstruction

Use the environment declared by the repository workflow as the initial reference environment:

- Ubuntu runner equivalent
- Python `3.10`

The operator must record the actual environment. If a dependency, package, runtime assumption, or operating-system requirement is absent from the repository and must be inferred externally, record it as a documentation gap under H-002.

## 6. Procedure

### Step 1 — Obtain the frozen release

Clone the repository and check out the exact `v0.5.0` release target. Verify the resulting HEAD against the canonical SHA above.

### Step 2 — Verify baseline integrity

Record repository state and hashes before execution. Do not edit tracked files.

### Step 3 — Run the declared O1 contract tests

```bash
python -m unittest discover -s tests -p 'test_o1_robustness_v0_5.py' -v
```

Record exit status and complete output.

### Step 4 — Execute the declared O1 procedure

```bash
python3 o1_robustness_v0_5.py \
  --engine value_flow_simulator_v0.4.py \
  --output-dir o1_evidence
```

The frozen O1 implementation declares the preregistered seed set:

```text
42, 137, 256, 512, 1024, 2048,
4096, 8192, 16384, 32768, 65536, 131072
```

Record the complete output directory and execution log.

### Step 5 — Prepare the independent evidence package

```bash
python3 prepare_o1_independent_evidence_v0_5.py \
  --evidence-dir o1_evidence \
  --commit "$(git rev-parse HEAD)"
```

Verify that the recorded commit equals the canonical v0.5 target.

### Step 6 — Run full regression

```bash
python3 -m unittest discover -s tests -p 'test*.py' -v
```

Record exit status and complete output.

### Step 7 — Run independent O1 evidence validation

```bash
python3 independent_o1_validator_v0_5.py \
  --evidence-dir o1_evidence \
  --regression-status regression_status.json \
  --commit "$(git rev-parse HEAD)"
```

Record the resulting validation JSON and all predicate/negative-case outcomes.

### Step 8 — Preserve the replication package

The replication package must include, at minimum:

- environment record
- exact commit/tag verification
- command transcript
- test outputs
- O1 execution log
- generated `o1_evidence/`
- regression status
- independent validation result
- SHA-256 manifest
- deviations and undocumented assumptions register

## 7. Predeclared success criteria

H-001/H-002 is **PASS** only if all of the following hold:

1. The operator reconstructs the exact canonical release target.
2. All required procedure inputs are available from the repository or explicitly documented dependencies.
3. The declared O1 procedure executes successfully for the preregistered seed set.
4. Required evidence artifacts are generated in the declared structure.
5. Full regression succeeds.
6. Independent O1 evidence validation succeeds.
7. Provenance in the produced package resolves to the exact replication commit.
8. No undocumented assumption is required to obtain the required outputs.
9. The complete replication package is preserved and independently inspectable.

A failure of any criterion prevents promotion of H-001/H-002 to demonstrated status.

## 8. Failure taxonomy

Classify failures before remediation:

- **F-R1:** repository artifact missing
- **F-R2:** procedure ambiguity
- **F-R3:** undocumented dependency/environment requirement
- **F-R4:** execution failure
- **F-R5:** artifact structure/provenance failure
- **F-R6:** independent validation failure
- **F-R7:** reproducibility mismatch

A failure must be recorded before changing the protocol or repository. Remediation is a separate controlled action.

## 9. Evidence boundary

This protocol can establish evidence about reproducibility of the declared v0.5 procedure. It does **not** establish:

- general reproducibility across arbitrary environments;
- scientific robustness beyond the declared O1 scope;
- general AI reliability or safety;
- validity of the broader ACAA epistemic architecture;
- any H-003+ hypothesis.

## 10. Current documentation-gap register

The initial repository audit found a usable executable O1 procedure and CI definition, including the seed set, Python 3.10 reference environment, test commands, execution command, evidence preparation, regression, and independent validation sequence. The following items remain to be explicitly recorded by the replication operator rather than inferred:

- exact external dependency installation procedure, if any;
- clean-environment setup procedure outside GitHub Actions;
- expected artifact manifest and SHA-256 values for a successful independent run;
- a canonical human-readable replication report template.

These are H-002 observations, not evidence of failure until tested by an independent operator.

## 11. Decision rule

No H-001/H-002 result is considered `DEMONSTRATED` until the replication package has been reviewed against this protocol and the Research Control Layer's `DEMONSTRATED / SUPPORTED / PROPOSED` ontology.

**Principle Zero:** ACAA must not grow faster than its evidence.
