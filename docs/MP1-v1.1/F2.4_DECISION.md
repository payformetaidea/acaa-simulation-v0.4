# F2.4 Decision — `date-time` Format Contract

**Status:** DECISION RECORDED / CONTROLLED FIXTURE RECLASSIFICATION AUTHORIZED

## Evidence basis

F2.4 execution run `31961079058` on commit `0e1b4b73c3c8d95c0366c751f9f625529ade205e` produced artifact `9267253458`.

Observed:

- frozen schema SHA-256: `624a2f8fea39cfa20440b8f53d3b500af710a54f76f12840ae1bbe0796fb68a7`
- frozen validator SHA-256: `30b62555377e1eac569c2ea7d08d66b6376257d492227fee271e830c567b10dc`
- schema dialect: Draft 2020-12
- `format-assertion` vocabulary: not declared
- `created_at` contains `format: date-time`
- jsonschema: `4.23.0`
- generic and Draft202012 `FormatChecker` registries did not contain `date-time`
- the invalid value was accepted by the isolated validator path

## Decision

`metadata.created_at.format = date-time` is **not a normative Layer-1 assertion in the frozen schema**. The frozen schema declares Draft 2020-12 but does not declare the Format-Assertion vocabulary.

Therefore `invariant-registry.invalid-date-time.json` was misclassified as a structural-negative fixture. Its expected Layer-1 failure cannot be justified by the frozen schema alone.

The fixture is reclassified as a **format-annotation / non-assertion test case** and moved out of the Layer-1 `invalid/` corpus. The original validator and schema remain unchanged.

## Consequence for S1-V

After the controlled fixture reclassification, S1-V must be rerun against the frozen validator target with the same validator code and schema. No validator correction is authorized by F2.4.

A future contract that requires `date-time` assertion MUST make that requirement explicit through the normative contract/dialect or a separately authoritative S1 rule before a validator change is considered.
